2. PLACA OLHO — Percepção de Bola e Ambiente

2.1 IR Seeker — 12 sensores TSOP

ParâmetroValor
Nº sensores12 TSOPs
Distribuição0° → 330° (passo 30°)
Janela de contagem15 ms
Limiar de pulsos≥ 8 pulsos → bola detectada
Amostras p/ votação5 amostras
Tolerância de voto45°

Os pinos dos 12 TSOPs são lidos digitalmente. Em uma janela de 15 ms, conta-se quantas transições HIGH→LOW ocorrem por sensor. Se um sensor detecta ≥ 8 pulsos, considera que vê o sinal IR da bola.

A direção da bola é calculada por média vetorial: cada sensor ativo contribui com um vetor unitário na sua direção angular, ponderado pelo número de pulsos. O ângulo final é atan2(Σy, Σx).

Pipeline de filtragem do ângulo IR

  • 1
    contarPulsosSensores() — janela de 15 ms, conta pulsos por sensor.
  • 2
    calculaAnguloBola() — média vetorial ponderada por pulsos.
  • 3
    filtrarAnguloBola() — repete 5 vezes, aplica votação por grupo: para cada amostra conta quantas outras estão a ≤ 45°, elege o grupo maior e retorna a média vetorial desse grupo. Elimina ruído e leituras espúrias.
Ângulo = −1 quando intensidade total = 0 (bola não detectada). O Músculo descarta leituras exatamente em 30° como artefato de sensor (eh30Graus = fabsf(novoAngulo − 30.0) ≤ 1.0).

3. PLACA PÉ — Detecção de Linha com 32 LDRs

3.1 Hardware — Multiplexadores CD74HC4067

MUXS0S1S2S3SIGSensores
MUX12147484530–15
MUX245671216–31

Cada canal é selecionado pelos 4 bits de endereço (S3…S0). O sinal analógico lido via analogRead(SIG) é comparado com o limiar LIMIAR_LINHA = 3850 (de 4095 = 12-bit ADC). Acima do limiar = linha branca detectada.

Tabela angular dos sensores (distribuição uniforme)

No setup(), cada sensor i recebe coordenadas:

sensorX[i] = cos(2π/32 × i) sensorY[i] = sin(2π/32 × i) // i = 0..31, passo 11.25°

3.2 Modos de operação — Atacante vs. Defensor

Modo ATACANTE — calcularAngulo(repulsao=true)

Calcula o centroide dos sensores ativos (ADC > 3850) e inverte o vetor (repulsão). O robô foge da linha na direção oposta ao centroide da linha detectada.

Envia struct Pacote — 2 bytes — com ângulo em décimos de grau.

Modo DEFENSOR — detectarLinhaDefensorPorZonas()

Divide os 32 sensores em Zona A (0-15, frontal) e Zona B (16-31, traseira). Calcula o centroide de cada zona separadamente (sem repulsão).

Zona B tem ângulo espelhado: angB = 540° − angB para referenciar corretamente 180°…360°.

Envia struct PacoteDefensor — 6 bytes — com anguloZonaA, anguloZonaB, temLinhaZonaA, temLinhaZonaB.

Cálculo do ângulo por centroide ponderado

for(i : sensores ativos onde ldr[i] >= LIMIAR_LINHA): centroX += ldr[i] * sensorX[i] centroY += ldr[i] * sensorY[i] soma += ldr[i] centroX /= soma ; centroY /= soma // repulsao=true: inverte vetor angulo = atan2(centroY, centroX) × 180/π → normaliza [0, 360)

O loop do Pé (delay 2 ms) envia Pacote se atacante == true, senão envia PacoteDefensor.

5. ESP-NOW — Comunicação entre Robôs

5.1 Struct EspNowMsg (23 bytes)

struct EspNowMsg { uint32_t seq; // contador sequencial uint8_t tipo; // 1=REQ, 2=RESP int16_t uD, uE, uF; // ultras locais ×10 int16_t uT; // TRASEIRO ×10 ← chave de papel char text[12]; // "ULTRA_REQ" ou "ULTRA_RESP" };

5.2 MAC alvo (hardcoded)

#define ESPNOW_TARGET_MAC_STR "AC:A7:04:2B:9B:60" // MAC da Cabeça do CRONOS (outro robô)

5.3 Temporizações

Envio periódico (REQ): 2 000 ms
Timeout link (sem RX + sem ACK): 6 000 ms
Status → Músculo (ESN:0/1): 500 ms
Retry inicialização (se falhar no boot): 2 000 ms

5.4 Lógica de link health

semRx = (millis() - espnowUltimoRxMs) > 6000 semAck = (millis() - espnowUltimoAckMs) > 6000 if(semRx && semAck) espnowComOK = false estado.sozinho = !espnowComOK || !espnowRecente

5.5 Troca automática de papel por ultrassônico traseiro

⚙ REGRA DE PAPEL (lógica futura — já estruturada no código)

Com 2 robôs online (espnowComOK = true):
  • Cada robô envia seu uT (ultrassônico traseiro ×10) via EspNowMsg.
  • Cabeça recebe o uT remoto em ultimoUltraRemotoTX10.
  • Menor uT → está mais perto da própria área → GOLEIRO
  • Maior uT → está mais avançado → ATACANTE

Link perdido (timeout > 6 s): robô restante permanece/vira ATACANTE.

Filtros recomendados para implementação: delta mín. 15 cm · janela 4 amostras consecutivas · cooldown 3 s entre trocas.

Variável de papel na Cabeça: bool atacanteCfg = true (linha 282 de cabeca.cpp). Alterar aqui propaga para Olho, Pé e Músculo via PacoteEstado + mensagem ATC:.

6. PLACA MÚSCULO — Controle de Movimento e Lógica de Jogo

6.1 Cinemática Omnidirecional (4 rodas Mecanum/Omni)

Ângulos físicos das rodas no referencial do robô:

θ₁ = 45°  θ₂ = 135°  θ₃ = 225°  θ₄ = 315°

Velocidade de translação em anguloGraus e velocidade:

vx = V·sin(θ)   vy = V·cos(θ)
v_i = vx·cos(θᵢ) + vy·sin(θᵢ)     i ∈ {1,2,3,4}

Se max(|v_i|) > velocidade_máxima, normaliza todos por esse máximo (preserva direção).

Para giro sobre o eixo: todos os motores com o mesmo comando (girarNoEixo(vel) → Motor_i(−vel)).

Para translação + giro simultâneo (seguirDirecaoComGiro): soma termo de giro ponderado (GANHO_GIRO_MISTO = 0.7) a todos os vetores de roda antes de normalizar.

7. LÓGICA DE JOGO — Modo ATACANTE

7.1 Prioridades de decisão (função atacante())

  • P1
    Fuga da linha — se linhaDetectada && anguloLinhaPe ≥ 0 (ou retenção de 250 ms): seguirDirecaoPorAngulo(anguloFuga, 255). O Pé já envia o ângulo em modo repulsão.
  • P2
    Giro total quando erro de gol grande — se |erroGol| > 40°: girarNoEixo(cmdPid). Para tudo para corrigir orientação.
  • P3
    IR frontal + giro suave — se IR detectado e anguloIR ∈ [340°, 360°] ∪ [0°, 20°]: moverFrenteComGiro(200, cmdPid). PWM frontal fixo em 200 com correção de heading simultânea.
  • P4
    IR lateral — se IR detectado: mapeia ângulo da bola para ângulo de movimento (ex: 45°→100°, 315°→260°, 90°→135°...), aplica rampa de 50-100 ms para suavizar transições, move com seguirDirecaoPorAngulo. Velocidade reduzida (140) nas faixas 15°-45° e 315°-345°.
  • P5
    Câmera substitui IR — se IR não detectado por ≥ 1 s e câmera vê bola: seguirDirecaoComGiro(angleCamBola, velocidade_max, cmdPid). Ignora linha neste estado.
  • P6
    Só giro de alinhamento — se gol visível mas IR e câmera-bola ausentes: girarNoEixo(cmdPid).
  • P7
    Para — nenhuma condição anterior satisfeita.

7.3 Suavização de ângulo IR (obterAnguloIrSuavizado)

Quando o ângulo alvo muda, inicia uma rampa linear de 50–100 ms (proporcional ao delta angular) para evitar salto abrupto de direção. Ao final, quantiza em passos de 5° para estabilidade.

8. LÓGICA DE JOGO — Modo DEFENSOR / GOLEIRO

8.1 Objetivo do defensor

Manter-se sobre a linha da área do seu gol, centralizado entre as Zonas A e B, enquanto rastreia lateralmente a bola com o IR.

8.2 Referências de zona

ZonaSensores PéReferência alvoInterpretação
Zona A0–15 (frontal)90°Linha à direita do centroide → move para trás; à esquerda → para frente
Zona B16–31 (traseira)270°Mesma lógica, espelhada (540° − angB)

8.3 Prioridades de decisão (função defensor())

  • P1
    Recuperação ao gol — se fora da linha E gol detectado pela câmera a dist > 46 px: move na direção do gol para reencontrar a linha.
  • P2
    Vetor combinado linha + lateral IR — calcula vyCmd (frente/trás pela linha) e vxCmd (lateral pelo IR). Combina em vetor único atan2(vx, vy) com pesos: linha ativa pesa 1.25×, lateral reduz para 0.35×.
  • P3
    Câmera sem IR — se câmera detecta bola a < 60 px e IR não detectado: move na direção da bola pela câmera.
  • P4
    Só giro de alinhamento — gira para frente a área.
  • P5
    Para.

8.4 Lógica de direção frente/trás pela linha

erroA = normalize(anguloZonaA − 90°) // erro da zona frontal erroB = normalize(anguloZonaB − 270°) // erro da zona traseira // sinal > 0 → move para trás (direcaoLinha = +1 → vyCmd -= vel) if(erroA > 0 && erroB < 0) → direcaoLinha = +1 (frente) if(erroA < 0 && erroB > 0) → direcaoLinha = -1 (trás) if(erroA > 0 || erroB > 0) → +1 ; if(erroA < 0 || erroB < 0) → -1 velocidadeLinha = proporcional à intensidade do erro (min: 90, max: 150)

10. PROTOCOLO DE COMUNICAÇÃO — Resumo Técnico

10.1 Protocolo binário (placa → Cabeça)

0xAAINÍCIO
→
ID0x01/02/03
→
STRUCT payload (N bytes)memcpy direto — sem serialização manual
→
0x55FIM

Motivação: zero overhead de parsing, velocidade máxima, sem ambiguidade de delimitador dentro do payload (structs nunca contêm 0xAA/0x55 por coincidência pois dados são int16 e o protocolo não usa escaping — risco aceitável por ser intra-placa).

10.2 Protocolo de texto ASCII (Cabeça → Músculo)

Linhas terminadas em \n, tamanho máximo do buffer = 32 chars. Músculo mantém buffer e despacha ao receber \n ou \r.
